## 已完成

### (1) 服務

- **不裝 web 框架。** 規格允許 pip 裝進 audio venv，但 `local_backend.py` 本身就用 stdlib 的
  `ThreadingHTTPServer`；照做零新依賴、風格一致，也不必動那個裝著數 GB 模型權重的 venv。
- `main()` 啟動前檢查 `LTX_AUDIO_HOST` 必須是 loopback，設成別的直接拒絕啟動。
- **路徑防護**：先 `resolve()` 再檢查是否落在 `uploads/`／`data/` 之內 —— 順序很重要，
  否則指向外部的 symlink 會通過檢查。實測擋下 `/etc/passwd`、`../../../etc/passwd`、
  專案內但不在允許目錄的檔案，以及逃逸用的 symlink。
- **whisper 延遲載入**：只在第一次 `/align` 才載入（數秒、約 6 GB）。只問拍點的主機不必付這個代價。
- `/beats` 回 tempo、beat 時間、段落邊界（MFCC 聚合分群）、能量曲線（RMS dB，每秒約 10 點）。
  段落分群失敗時回空陣列而不是整個失敗 —— 極短或近乎無聲的檔案沒有編曲可分，但拍點仍然成立。

### (2) 對外端點

`POST /api/v1/audio/analyze {audio_id, lyrics?, language?}`

- 檢查 asset 種類與**所有權**（非本人 → 403），再由 API 解析路徑；服務never 看到 asset id 或帳號。
- **快取放 `data/worker/audio-cache/`，不是 uploads/** —— `list_assets()` 會 glob `uploads/*.json`，
  放在那裡的側車檔會被當成壞掉的素材讀回來。快取鍵含檔案 size 與 mtime，以及歌詞與語言的
  雜湊：換一份歌詞就是不同的問題，要重算。
- 回傳附 `lyric_offset_seconds`（預設 −0.9）與說明文字，明確寫出「這是常數偏移不是隨機誤差，
  比較前先扣掉，且每個來源都該重新校準」。
- **服務不可用回 503，不影響生成**：分析是輔助不是前提。測試實際驗證了服務掛掉時
  `/api/v1/validate` 仍然 200。

### (4) 測試

`tests/test_audio_service.py` 設計成**兩個直譯器各跑自己負責的部分**：

| 直譯器 | 有什麼 | 跑哪些 |
|---|---|---|
| LTX venv | psycopg、無 librosa | 端點測試（所有權、快取、503、歌詞分流） |
| audio venv | librosa、無 psycopg | 分析測試（路徑防護、symlink、拍點） |

模組層的 import 改成條件式，兩邊都不會因為缺對方的套件而整檔失敗。合成點擊音由 numpy 產生，
不需下載任何模型。需要 whisper 的整合測試以 `LTX_AUDIO_INTEGRATION=1` 開啟。

### 啟用 ltx-audio.service（系統層級，需核准）

```text
【需要核准：OP-AUDIO01】
目的：讓 ltx-api 能呼叫音訊分析服務。
準備執行：cp infra/systemd/ltx-audio.service ~/.config/systemd/user/ 後
          systemctl --user daemon-reload && systemctl --user enable --now ltx-audio.service
異動的檔案或服務：~/.config/systemd/user/ltx-audio.service；新增一個常駐 user service
影響與風險：常駐約 200 MB（librosa）；第一次 /align 會再載入 whisper 約 6 GB，與 LTX 可並行。
          只聽 127.0.0.1:8790，外部不可達。不影響既有服務。
復原方式：systemctl --user disable --now ltx-audio.service 並刪除 unit 檔。
請回覆「核准 OP-AUDIO01」或「拒絕 OP-AUDIO01」。
```

**未啟用不擋合併**：`/api/v1/audio/analyze` 在服務不在時回 503，生成完全不受影響。
