# B4 LLM 編劇草稿

規格：`docs/PRODUCTION_ROADMAP.md` 的 B4 節。分支 `wo/b4`。

## 已完成

- `db/migrations/0003_draft_usage.sql` — `projects.draft_usage jsonb`。
  用一個 jsonb 欄位而非每次呼叫一列：上限要的是累計值，逐筆列會無上限成長而沒人會逐筆讀。
- `factory_store.py`
  - `draft_context(shot_id, owner_id)` — 一次 owner-checked 讀取，帶回該鏡、Bible、**前後鏡**與目前用量。
    前後鏡是必要的：沒有它們，草稿會重複上一鏡的取景。
  - `add_draft_usage(project_id, tokens)` — 用 jsonb 算術在單一 statement 內累加，
    兩個同時發出的草稿不會各自讀到舊值再寫回同一個數字（那樣上限永遠到不了）。
- `local_backend.py`
  - `POST /api/v1/factory/shots/{id}/draft` — key 讀 `/opt/studio/secrets/openai`，
    **權限不是 0600 就當成沒有 key**（把 key 擋在瀏覽器外，卻讓本機任何帳號讀得到，等於白做）。
    structured output `strict: true`，只回 `{prompt, primary_action}`，多的欄位丟掉。
  - 每專案 token 上限（`LTX_DRAFT_TOKEN_LIMIT`，預設 200000），**超過在呼叫前就回 429**。
  - 服務不可用 503、答案讀不懂 502（且不計費）。
  - `/api/v1/capabilities` 加 `draft_available` 布林與 `draft_token_limit`，不洩漏 key。
- `tests/test_factory_draft.py` — 13 個測試，全部 mock，不打真 API。
