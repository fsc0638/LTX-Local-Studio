# B4 LLM 編劇草稿

規格：`docs/PRODUCTION_ROADMAP.md` 的 B4 節。分支 `wo/b4`。

## 已完成

- `db/migrations/0003_draft_usage.sql` — `projects.draft_usage jsonb`。
  用一個 jsonb 欄位而非每次呼叫一列：上限要的是累計值，逐筆列會無上限成長而沒人會逐筆讀。
- `factory_store.py`
  - `draft_context(shot_id, owner_id)` — 一次 owner-checked 讀取，帶回該鏡、Bible、**前後鏡**與目前用量。
    前後鏡是必要的：沒有它們，草稿會重複上一鏡的取景。
  - `add_draft_usage(project_id, tokens)` — 用 jsonb 算術在單一 statement 內累加，
    兩個同時發出的草稿不會各自讀到舊值再寫回同一個數字（那樣上限永遠到不了）。
- `local_backend.py`
  - `POST /api/v1/factory/shots/{id}/draft` — key 讀 `/opt/studio/secrets/openai`，
    **權限不是 0600 就當成沒有 key**（把 key 擋在瀏覽器外，卻讓本機任何帳號讀得到，等於白做）。
    structured output `strict: true`，只回 `{prompt, primary_action}`，多的欄位丟掉。
  - 每專案 token 上限（`LTX_DRAFT_TOKEN_LIMIT`，預設 200000），**超過在呼叫前就回 429**。
  - 服務不可用 503、答案讀不懂 502（且不計費）。
  - `/api/v1/capabilities` 加 `draft_available` 布林與 `draft_token_limit`，不洩漏 key。
- `tests/test_factory_draft.py` — 13 個測試，全部 mock，不打真 API。

- UI（`components/production-factory.tsx`、`app/page.tsx`、`lib/video-settings.ts`）
  - 每鏡提示詞旁「起草」按鈕，`draft_available` 為 false 時停用並顯示原因。
  - **提示詞已 pinned（使用者自己寫過，或採用過上一份草稿）時，草稿不覆蓋**：
    改成在旁邊以虛線框呈現建議，附「採用／不用」。未 pinned 才直接填入。
  - 採用時會 pin 提示詞 —— 沒 pin 的提示詞會在下次 Bible 重新投影時被清掉，
    pin 才代表「這是個決定」。
  - 三語系文案齊備。

## 已驗（隔離實例，真 OpenAI）

正式站的 ltx-api 跑在 main 上、沒有 `/draft`，所以 dev server 接它時按鈕必然是灰的
（那是正確行為，不是 bug）。改用隔離實例驗完整流程：port 8788、`ltx_studio_test` 資料庫、
獨立 work dir、`LTX_UPLOAD_DIR` 指向正式素材（唯讀使用）。

- 真實 OpenAI 呼叫兩次：計費 519 → 926 tokens 正確累加；回應只有 `prompt` 與
  `primary_action`，`capabilities.draft_available=True`。
- 草稿確實用上 Bible 角色描述、導演參數（golden hour／slow dolly in）與歌詞行。
- 阿寶在瀏覽器實測流程與功能正常（2026-09-06）。

**設定上踩到的坑**（給下次的人）：`media_store.UPLOAD_DIR` 在 import 時就 `resolve()` 定案。
先啟動 API、事後才建 `uploads` 符號連結，會讓 `asset_path()` 的
`path.resolve().parent != UPLOAD_DIR` 永遠成立，每個素材都被判成「找不到」。
用 `LTX_UPLOAD_DIR` 明確指定，不要靠連結。
