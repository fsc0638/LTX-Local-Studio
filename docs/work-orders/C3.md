# C3 審片頁

規格：`docs/PRODUCTION_ROADMAP.md` 的 C3 節。分支 `wo/c3`。

## 已完成

- **規格衝突先講清楚**：C2 時我把「被另一個 take 取代」標成 `overridden`；C3 規格定義
  `overridden`＝紅燈下人仍接受。以規格為準：被取代的 take 回 `pending`（它又是沒人選的 take，
  這是實話），`overridden` 專指人推翻裁判，並記錄 `overridden_by`／`overridden_at`。C2 的測試同步改。
- `db/migrations/0005_review.sql` — `takes.overridden_by`、`overridden_at`、`opinion`。
- `review_rules.py` — 門檻與燈號的**單一規則**（API 與測試共用）。
  - 預設 `cj 0.80 / sj 0.85 / mq 0.50`，`calibrated: false`；架構頁的暫定值，C4 校準後由 Bible 覆蓋。
    優先序：本鏡 `request.thresholds` ＞ `bible.thresholds` ＞ 預設。嚴格模式用 `bible.thresholds.strict`
    或預設嚴格值（`cj 0.85 / sj 0.90`）。
  - `mq` 分數＝`1 − frozen_ratio`（靜態圖為 None）。
  - **未判分不是紅燈。** 裁判掛掉、沒有參照圖、靜態圖沒動態——都不是對 take 不利的證據，
    所以都不亮紅。有測試。
- `factory_store.py`
  - `accept_take()`：**燈號在伺服器端由存的分數算**，不信客戶端說的。紅燈下接受 → `overridden`
    + 誰／何時；綠燈或未判分 → `accepted`。前一個被選的 take → `pending`、清掉 override 記錄。
  - `take_context()`、`record_opinion()`、`disagree_opinion()`（句子留著、記誰不同意）、
    `project_takes()`（整個專案的 take 依鏡分組，附每個 take 的門檻與燈號——審片頁一次拿）。
- `local_backend.py`
  - `GET /projects/{id}/takes`；`POST /takes/{id}/accept {strict?}`；`/disagree`；
    `POST /takes/{id}/opinion`：gpt-5.6 看 poster 幀 + 裁判數字，回**一句**繁體中文；
    走 B4 同一把 key、同一個 token 預算（超過 429，且在呼叫前就擋）；沒 poster 回 400 不花錢。
- `tests/test_factory_review.py` — 20 個新測試（規則 5、API 15，全 mock）。

- `lib/review.ts` — 瀏覽器端同一套規則；`tests/review.test.mjs` 與 `test_factory_review.py`
  用**同一組 fixture 數字**（RED／GREEN／UNSCORED），兩邊漂移會變成測試失敗而不是畫面與紀錄不一致。
- `lib/stages.ts` — `review` 不再是「本期未啟用」：有完成卻沒 verdict 的鏡 → `attention`；
  全部有 accepted take → `done`；否則 idle。`status-board` 補 `resultReviewed`／`nextReview` 三語。
- `components/review-board.tsx` — 每鏡 take 並排（poster、verdict、三條分數 vs 門檻刻度、燈號）；
  未校準 banner；相鄰鏡嚴格模式開關（同時影響採用時的判定）；VLM 一句話＋「我不同意」（劃線保留）；
  採用（紅燈先確認，說明會記錄誰／何時）；退回必填原因；抽屜：逐幀 CJ 曲線（點色依門檻）、
  本鏡門檻覆寫（存進 `shot.request.thresholds`，只影響該鏡）。裁判關閉時分數欄顯示「未判分」並註明不是紅燈。
- `app/page.tsx` — 04 分頁接上；三語文案。
- **順手修一個資料流失路徑**：`ProductionFactory` 只在 running 時輪詢，審片退回後伺服器已把 prompt
  加上「避免：…」，03 頁面的副本卻還是舊的，下一次存檔會把舊 prompt 蓋回去。加 `hostVersion` prop：
  審片動作後頁面遞增，元件從主機重載（沿用既有 `getProject → setPlan` 路徑）。
