### (3) 進行中 — `production_store.py` 已完成

- `ProductionStore(path)` → `ProductionStore(url=None)`，預設讀 `LTX_DATABASE_URL`。
  **不再自己建表**：schema 歸 `db/migrations` 所有，由 API 啟動時套用；store 自建表會與 migration
  歷史分岔。
- 佔位符 `?` → `%s`；`json_extract(snapshot,'$.x')` → `snapshot->>'x'`；`created_at` 比較需要
  `(snapshot->>'created_at')::double precision`（`->>` 回傳文字，不轉型會變成字串比較）。
- 讀取端不再 `json.loads`：jsonb 直接回 dict，`row["snapshot"]` 就是原本的形狀。
- `local_backend.py`：`ProductionStore()` 改吃 DSN；例外攔截 `sqlite3.Error` → `psycopg.Error`
  （否則 store 初始化失敗不會被接住）。

### (3) 續 — `AuthStore` 與 API 層完成

- `user_auth.py`：`AuthStore(path)` → `AuthStore(url=None)`，同樣不再自建表。
  SQLite 的 `BEGIN IMMEDIATE` 在 PostgreSQL 沒有對應物，改成明確的列鎖：
  - `rate()`：`SELECT ... FOR UPDATE` 序列化同一 scope 的併發檢查，避免兩個請求都讀到未達上限
    後各自 +1。`ON CONFLICT DO UPDATE` 需寫成 `rate_limits.count+1`（SQLite 允許裸 `count`）。
  - `issue_email_token()`、`consume_token()`：同樣以 `FOR UPDATE`（後者用 `FOR UPDATE OF t`
    只鎖 token 列，不鎖 users）。
  - `(?=0 OR ...)` 需寫成 `(%s::int=0 OR ...)`，否則參數型別不明確。
  - `sqlite3.IntegrityError` → `psycopg.errors.IntegrityError`。
  - `PRAGMA foreign_keys=ON` 移除：PostgreSQL 一律強制外鍵，沒有 per-connection 開關。
- `auth_http.py`、`local_backend.py`：17 + 4 處 `sqlite3.Error` / `sqlite3.OperationalError`
  例外攔截改為 psycopg 對應物；`AuthStore()` 改吃 DSN。核心程式已無 sqlite3 引用。

實測（`ltx_studio_test`）：

```

未驗證信箱登入 → email_not_verified               → OK
60 秒內重發 email token → rate_limited            → OK
consume_token 驗證 → verified_at 設定             → OK
login / session / logout                          → OK
rate() 第 4 次 → rate_limited                     → OK
```

### (3) 測試隔離 — 完成，120 項全過

- `tests/conftest.py`：名字沿用 pytest 慣例，但**不依賴 pytest** — 自檢用的是
  `unittest discover`，所以測試明確 `import conftest`。
- **隔離方式改成每測試 TRUNCATE，不是規格寫的交易回滾。** 規格那個做法在這裡行不通：
  `BackendTests` 會起 `ThreadingHTTPServer`，請求處理在別的執行緒呼叫 store；一條 psycopg 連線
  不能被多執行緒併發驅動，跨執行緒巢狀交易會炸出 `OutOfOrderTransactionNesting`（實際踩到）。
  改用 TRUNCATE 後 store 照常各自開連線，測試走的是與正式環境相同的連線路徑。
- 安全閥：`LTX_TEST_DATABASE_URL` 的資料庫名不含 `test` 就拒絕執行（會 TRUNCATE 每張表）。
  解析 DSN 用 `urlsplit` 而非切 `/` — DSN 裡的 `host=/var/run/postgresql` 會讓後者取錯。
- 測試檔調整：`ProductionStore(path)`／`AuthStore(path)` → 無參數；不繼承 `BackendTests` 的
  `EnrollmentTests`、`ArchiveTests` 各自加上 fixture；測試內的原生 SQL 佔位符與位置索引
  （`fetchone()[0]`）改為 `%s` 與欄位名。
- **`cloudflare_access.py` 另有 4 處帶 `?` 的原生 SQL**，先前漏掉（該檔沒有 import sqlite3，
  只用 `store.connect()`），一併移植。
- `scripts/clear-media.py` 移植：PostgreSQL 沒有 `sqlite3.db.backup()` 的 in-process 等價物，
  改成把即將被標記刪除的列匯出成 `jobs-before.json`。同樣的安全網，而且不需要資料庫就能讀。
  `json_set` → `jsonb_set(...,'{deleted_at}',to_jsonb(%s::double precision))`。

### (4) 搬移腳本 — 完成並演練

`scripts/migrate-sqlite-to-postgres.py`：只讀 SQLite → 寫 PostgreSQL → 逐表比對 → 印報告。

### 已處理：OP-PG5432（只走 unix socket）

阿寶核准並執行 `ALTER SYSTEM SET listen_addresses = ''` + 重啟。驗證：

```
ss -ltn | grep -c ':5432'                        → 0
psql postgresql:///ltx_studio?host=/var/run/...  → kwayrdc@ltx_studio
psql postgresql://kwayrdc@127.0.0.1:5432/...     → 連線被拒絕
```

用 `ALTER SYSTEM` 而非直接改 `postgresql.conf`，設定寫進 `postgresql.auto.conf`，
不動 Ubuntu 原始設定；回復是 `ALTER SYSTEM RESET listen_addresses` + 重啟。
驗收「`ss -ltn` 看不到 5432」現在字面通過。
