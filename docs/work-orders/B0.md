### (2) baseline migration、runner、環境變數 — 完成

- `db/migrations/0001_baseline.sql`：**六張表**，不是規格寫的三張。實際的 `accounts.sqlite3` 有
  `users`／`sessions`／`email_tokens`／`rate_limits`／`cloudflare_enrollments` 五張，加上
  `jobs.sqlite3` 的 `jobs`。規格那句「jobs、accounts、cloudflare_enrollments 三表」是簡寫，
  照實際 schema 實作。
- 形狀刻意保留，讓第 (3) 步改寫後呼叫端拿到的東西不變：epoch 秒數維持 `double precision`
  （程式當浮點數比較，不改成 timestamptz）、`users.disabled` 維持 integer 0/1 不改 boolean。
  唯一刻意的改變是 job snapshot `TEXT` → `jsonb`，這正是表達式索引不必再靠 `json_extract()` 的原因。
- `database.py`：`database_url()`（**沒有 SQLite fallback**，缺變數就 `RuntimeError`）、
  `connect()`（`dict_row`，讓呼叫端跟過去 `sqlite3.Row` 一樣用欄位名取值）、`apply_migrations()`
  （每支 migration 各自一個交易，失敗時已套用的仍記錄，重跑會接續而非從頭）。
- `local_backend.py`：啟動時在 instance lock 之內套用 migration，失敗直接 `SystemExit`；
  兩個 API 實例不會同時改 schema。

### 一個安全性偏差，需要你決定

規格的驗收寫「`ss -ltn` 看不到 5432 — 只有 unix socket」。實際安裝後 5432 **有**在監聽，
但只綁 `127.0.0.1`（Ubuntu 預設 `listen_addresses = 'localhost'`）：

```
ss -ltn → LISTEN 127.0.0.1:5432
從 192.168.1.106 連 5432 → 連線被拒絕
```

也就是**外部連不到**，安全意圖已達成，只是不符驗收的字面。要完全符合需要改
`/etc/postgresql/16/main/postgresql.conf` 的 `listen_addresses = ''` 並重啟 postgresql —
這是系統層級動作，見下方核准區塊。不改也可以，那就把驗收文字改成「只綁 loopback」。
