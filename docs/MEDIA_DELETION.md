# 媒體刪除與私有回收區

成品預覽、產出列表及上傳素材卡片提供「刪除」按鈕，沿用本站中／英／日語系及確認視窗樣式。刪除已選取的參照素材時會一併取消選取。

## 通用 API

- `DELETE /api/v1/jobs/{id}`：刪除已結束任務的成品、預覽圖與媒體描述檔。任務清單不再顯示該筆，原成品網址回傳 404。
- `DELETE /api/v1/assets/{id}`：刪除上傳的圖片或影片及描述檔。
- 不接受 request body。瀏覽器需帳號登入與 `X-CSRF-Token`；伺服器對伺服器可使用既有 Worker Bearer。外網仍須通過 Cloudflare Access。
- 帳號只能刪除自己的項目；不存在或他人項目回傳 404，服務金鑰具主機管理權限。
- 正在執行或排隊的任務回傳 409 `job_active`；正在被生成任務使用的素材回傳 409 `asset_in_use`。取消後需等工作真正停止。
- 成功回傳 `{"deleted":true,"recoverable":true}`。若檔案移除失敗但任務墓碑已持久化，額外回傳 `cleanup_pending:true`；下載仍被拒絕，管理者需檢查原路徑。
- 任務保留不可由一般 API 覆寫的 `deleted_at` 墓碑、配額及冪等性紀錄。相同冪等性鍵重送已刪除任務回傳 410 `job_deleted`，不會偷偷重新生成；再次生成需新鍵。

## 可復原範圍

檔案先以 hard link 留存在 `data/worker/trash/media-*/`，寫入 `manifest.json` 後才移除原路徑。回收區限本機服務帳號讀取（0700），不對外提供 URL。此操作是從服務中移除，**不是永久抹除，也不立即釋放檔案佔用的磁碟容量**。已下載到其他裝置或已緩衝播放的副本無法回收。

禁止符號連結及跨檔案系統刪除；若部署將媒體搬到另一磁碟，需先調整回收區設計。網頁沒有復原或清空回收區按鈕，避免重新公開使用者已刪除的檔案。

管理者復原前須停機、取得使用者同意、確認 manifest 的原位置與所有權，並先備份目前資料庫。檔案應從回收區複製，不可覆蓋較新的原檔；成品還需針對該任務移除墓碑才能重新發布。不可直接覆蓋整個 jobs 資料庫，否則可能丟失後續任務。部分失敗的歸檔可能只有部分 hard link，須逐檔核對。

## 整批清理（主機管理者）

1. 先執行 `python3 scripts/clear-media.py` 唯讀盤點。
2. 等生成結束，停止本機 API 及正式版網頁服務。腳本必須取得與 API 相同的 instance lock；有排隊／執行中任務則拒絕清理。
3. 執行 `python3 scripts/clear-media.py --apply`。依腳本列出的固定目錄清理現行成品、上傳素材、舊版範例、測試產出及生成工作檔。保留 `.gitkeep`。
4. 腳本輸出回收區位置、檔案數量與大小。批次回收區額外保留清理前 `jobs-before.sqlite3`；帳號資料庫、登入紀錄、模型、金鑰、環境設定、既有備份及品牌圖片完全不在清理範圍。
5. 啟動服務，檢查 `/api/outputs`、`/api/v1/jobs`、`/api/assets` 為空；確認帳號與 Cloudflare 邊界仍正常。

此腳本針對預設本機目錄配置；若另設自訂輸出／上傳目錄，應先檢查部署配置，不可把任意路徑加入清理範圍。
